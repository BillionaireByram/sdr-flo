# FLO Core Taxonomy — SDR Flo Mapping

## Product rule

**DigitalFlo sells FLO.** A client buys FLO for Sales, Growth, Ops, or Tech. This repository is the canonical **internal acquisition framework** for the Sales Flo department.

```text
FLO
└── Sales Flo
    └── SDR Flo (this framework)
        ├── Setter Flo — lead-conversation function
        └── Sales Flo intelligence — back-office lead/pipeline intelligence
```

## Naming rules

- **SDR Flo** remains this repository’s canonical technical framework name.
- **Setter Flo** remains the internal term for the lead-facing qualifier/booker.
- **Sales Flo intelligence** remains the internal term for metrics, lead intelligence, call review, and pipeline reporting.
- In client scope and commercial language, all three are simply **Sales Flo** inside **FLO**.
- To a lead, use only the configured persona—usually “Flo,” or the client’s brand/persona. Never expose framework or tool names.
- Ads Flo, Marketing Flo, Funnel Flo, and Design Flo belong to **Growth Flo**; they are not part of SDR Flo’s product name.
- A vertical is `FLO for [industry]`; do not create a new `X Flo` brand for a niche.

## No-breakage rule

Existing service names, database tables, templates, and config identifiers remain stable. This product taxonomy changes language and routing, not live infrastructure.
